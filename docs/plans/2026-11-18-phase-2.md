# Phase 2 Implementation Plan

> Execute sequentially with the executing-plans workflow. The user has authorized implementation, one task at a time. Keep this checklist current; no automatic commits, pushes, agent config edits, real transcript reads or model downloads.

**Goal:** Demonstrate a project-scoped memory handoff between two MCP clients with measured retrieval quality, token usage and memory.

**Architecture:** One local Python service owns SQLite and eventually one optional embedder. Structured agent writes are primary; lexical retrieval works offline without any model. See ARCHITECTURE.md and research/04-mcp-and-retrieval.md for the contract and data model.

**Tech Stack:** Python 3.12+, stdlib sqlite3/TOML/argparse initially; later strict JSON Schema validation, FastAPI, Python MCP SDK, sqlite-vec and optional FastEmbed.

**Execution rule:** Complete one numbered task, run its acceptance checks, record evidence, then proceed to the next in order. Each task follows failing behavioral tests → minimal implementation → focused tests → full checks. Keep dependencies limited to the current task. Separate tasks are logical units within this repository, not parallel agents/worktrees.
