# Phase 2 Implementation Plan

> Execute sequentially with the executing-plans workflow. The user has authorized implementation, one task at a time. Keep this checklist current; no automatic commits, pushes, agent config edits, real transcript reads or model downloads.

**Goal:** Demonstrate a project-scoped memory handoff between two MCP clients with measured retrieval quality, token usage and memory.

**Architecture:** One local Python service owns SQLite and eventually one optional embedder. Structured agent writes are primary; lexical retrieval works offline without any model. See ARCHITECTURE.md and research/04-mcp-and-retrieval.md for the contract and data model.

**Tech Stack:** Python 3.12+, stdlib sqlite3/TOML/argparse initially; later strict JSON Schema validation, FastAPI, Python MCP SDK, sqlite-vec and optional FastEmbed.

**Execution rule:** Complete one numbered task, run its acceptance checks, record evidence, then proceed to the next in order. Each task follows failing behavioral tests → minimal implementation → focused tests → full checks. Keep dependencies limited to the current task. Separate tasks are logical units within this repository, not parallel agents/worktrees.

## Task 2 checkpoint — 2026-11-18

Implemented stdlib-only `brain.projects` and `brain project resolve --cwd PATH --data-dir PATH`. Persistent common-directory aliases group linked worktrees; conservative supported-origin normalization groups independent clones without persisting credentials. Originless repositories stay isolated; non-repo directories explicitly resolve to global. A first unclaimed origin can join a local-only identity; changed established origins and conflicting aliases require review and do not mutate mappings. Explicit remapping/merging remains unimplemented.

Resolver reads only local Git metadata with a timeout, ignores inherited GIT_* overrides/global/system config and config includes, never fetches/checks out or invokes hooks, and fails closed for malformed URLs, multiple origins, bare repositories and broken Git metadata. Alias creation uses one BEGIN IMMEDIATE transaction; active caller transactions are rejected without being committed/rolled back. Unknown-host scp-style and local/file origins are deliberately rejected rather than guessed; custom-host HTTPS/absolute SSH remain transport-specific.

Evidence: 14 new project tests plus the original 13 bootstrap tests pass (27 total), including disposable real worktrees/local clones, symlink aliases, credential stripping, path case/nondefault ports, changed/ambiguous aliases, concurrent resolution, malformed/broken metadata and CLI outcomes. Ruff, formatting, strict MyPy, package build and Bandit medium/high checks pass. Bandit retains one low-severity subprocess-import advisory; the fixed local Git invocation has a documented B603 suppression (absolute executable, fixed metadata commands, no shell). Isolated wheel installation with no runtime dependencies also resolves two synthetic equivalent origins to the same project ID outside the repository.

No user Git config/remotes, real agent sessions or client configs were changed. No commits or pushes made for Task 2. Task 3 (strict contracts and privacy boundary) is next; memory writes/retrieval, MCP and embeddings remain pending.
