# Phase 2 Implementation Plan

> Execute sequentially with the executing-plans workflow. The user has authorized implementation, one task at a time. Keep this checklist current; no automatic commits, pushes, agent config edits, real transcript reads or model downloads.

**Goal:** Demonstrate a project-scoped memory handoff between two MCP clients with measured retrieval quality, token usage and memory.

**Architecture:** One local Python service owns SQLite and eventually one optional embedder. Structured agent writes are primary; lexical retrieval works offline without any model. See ARCHITECTURE.md and research/04-mcp-and-retrieval.md for the contract and data model.

**Tech Stack:** Python 3.12+, stdlib sqlite3/TOML/argparse initially; later strict JSON Schema validation, FastAPI, Python MCP SDK, sqlite-vec and optional FastEmbed.

**Execution rule:** Complete one numbered task, run its acceptance checks, record evidence, then proceed to the next in order. Each task follows failing behavioral tests → minimal implementation → focused tests → full checks. Keep dependencies limited to the current task. Separate tasks are logical units within this repository, not parallel agents/worktrees.

## Task 4 checkpoint — 2026-11-23

Implemented `brain.ledger.record_memory(connection, payload, principal_id=..., authorized_projects=..., max_pending_work=1000)` and synthetic ledger tests. It always calls the Task 3 preparation boundary, requires a provisioned authorized project and idle initialized connection, and uses BEGIN IMMEDIATE for receipt replay/CAS, source references, immutable revisions/events/relations, acceptance/conflict projections, FTS documents and bounded indexing jobs. Caller transactions are rejected without mutation. Trusted in-process principal/project capabilities must come from transport credentials in Task 7; this function is not authentication or a public CLI.

Canonical sanitized requests determine project/principal/operation-scoped idempotency: replay returns the original acknowledgement, changed sanitized payloads reject. Structured writes have no ingest manifest: canonical sanitized Source metadata determines a structured-v1 source reference/digest (not a transcript-body digest). Exact statement/payload/validity hashes support an existing assertion without duplicate revisions; new sources append support and repeated source evidence is a noop. Accepted and pending candidates both receive evidence without promoting pending candidates. Exact identity includes project, type, entity, key and applicability scope; changed cardinality or ambiguous multi-memory identities reject.

Changed Decisions/Constraints always become pending_review. Differing TechStack/BugFix claims also require review unless expected/superseded heads identify an explicit forward-effective replacement. This conservative first writer does not infer prose equivalence or set-member compatibility: differing set-valued claims also require review before coexistence (Task 5). TaskState requires known increasing valid_from and accepted-head CAS. Allowed set transitions: todo → in_progress/blocked/cancelled; in_progress → blocked/done/cancelled; blocked → todo/in_progress/cancelled. Done/cancelled can return to todo/in_progress only with reopen. Initial known-time snapshots use set. Exact historical evidence remains support, not a state transition.

Supersession appends close/supersede/accept events; immutable revision intervals remain unchanged. Earlier knowledge segments are retained, with a new old-fact prefix projection ending at the effective boundary. Unknown validity remains explicit for non-TaskState cards. Reads, review authorization/resolution and broader backdated correction/rollback behavior remain later tasks. FTS is updated transactionally even without embeddings; acknowledgements say degraded when semantic work is absent and pending when queued. Jobs are emitted only for explicitly enabled generations, with a default global cap of 1000 pending/leased work items; capacity failure rolls back the whole write. No model dependency or worker added.

Evidence: 12 new ledger tests, 55 total tests passing. Covers replay/collision/support/noop, pending-candidate support, Decision/Constraint conflicts, CAS, forward-effective replacement and immutable original validity, task ordering/transitions/reopening, unknown validity, scope isolation/privacy, concurrent replay, queue capacity and injected SQL failures in acceptance/search/outbox/receipt writes, including rollback of a replacement's segment changes. ## Task 5 checkpoint — 2026-11-26

Added in-process `search_memory`, `get_project_context`, `get_history` and `resolve_conflict` APIs in retrieval/history/review modules, with canonical packing and snapshot helpers in budget.py. All inputs pass the existing preparation/privacy boundary and successful outputs are schema validated. Callers supply authorized read projects or a separate review-project capability; credential authentication remains Task 7. No public commands or transports were added.

Reads capture one world-time/knowledge snapshot, exclude unknown validity with a diagnostic, enforce project opt-in, and filter eligibility before FTS ranking/candidate limits. Exact identity is an independent candidate channel. Lexical/exact RRF uses weights 1/2, rank offset 60 and 128 candidates per channel with explicit candidate_limit diagnostics. No-goal context orders by type, primary project, acceptance sequence and stable IDs. Unresolved conflicts are reconstructed at the requested knowledge cutoff, warn independently of items and withhold affected memory streams. Overlapping distinct single-valued accepted revisions fail safely. Reads have a two-second SQL progress deadline and reject eligible scans beyond 10000 rows; deadlines are resource limits, not latency measurements. SQLite busy timeout remains separately bounded by database initialization.

Budgets count canonical data JSON including provenance, diagnostics, warning counts and their own used field. The byte fallback explicitly reports utf8_upper_bound; callers can inject a trusted pinned TokenCounter for configured counting. Packing reserves warnings, reports exact omitted warning counts, and skips oversized whole items while trying later items. History stops before oversized events, pins through_seq and returns the last emitted sequence for continuation; a first event that cannot fit raises budget_too_small. In-process failures carry bounded ReadError codes (or existing ContractError validation failures); transport error envelopes remain Task 7.

Review supports keep_existing, accept_candidate and compatible coexistence with idempotent receipts, conflict-head CAS and immutable action/rationale/effective-time details. Candidate acceptance preserves earlier knowledge and old valid-time prefixes; single-valued coexistence requires disjoint known intervals, while explicit set-valued coexistence is allowed. New supporting evidence advances pending conflict heads, preventing stale review. Acceptance changes invalidate other pending conflict heads; stale accepted heads reject. All review events, relations, projections and receipts commit atomically. No Phase 3 rollback CLI or model worker was added.
