## 4. Original MCP Server & Token-Budgeted Retrieval Layer

### 4.1 Transport and service boundary

One Python service owns SQLite, its write queue and the only ONNX session. Use FastAPI loopback HTTP for local API and mount the Python MCP SDK's Streamable HTTP endpoint at `/mcp`. Thin stdio adapters forward MCP protocol messages to that service without importing the embedder. CLI/IDE clients can use either transport as supported. Avoid an independent database/model instance per agent. Pin compatible SDK/protocol versions during implementation and negotiate versions normally; do not assume every client accepts the newest draft.

The public [MCP tools specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) defines schema-bearing tool discovery and structured results. Use the [standard transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports): stdout contains only protocol messages for stdio; Streamable HTTP replaces legacy HTTP+SSE. A legacy SSE endpoint is deferred until a real testbed requires it.

Require a locally provisioned credential and scoped principal on HTTP, validate Host and Origin, bind only loopback, and grant stdio adapters equivalent narrowly scoped access. Browser companion credentials are separate, write-only and project/adapter-scoped; reject credentials in query strings. Only explicitly paired extension origins may access `/ingest`; general provider web origins do not receive the engine credential. No wildcard CORS. Reauthentication remains inside the companion. MCP server session IDs are not authorization credentials. Limits apply before JSON parsing; logs never include authorization headers or source payloads.

### 4.2 Contract registry, errors and invariants

The JSON block below is the normative draft-2020-12 schema registry. For each named tool T, publish `TInput` as inputSchema and `TOutput` as outputSchema, with root `type: "object"` and this registry's `$defs` copied into each exported schema so local references resolve without network access. `/ingest` uses `ingestInput` / `ingestOutput`. All objects reject unknown properties. All listed properties are required; nullable values are explicit, not omitted. Empty `types` means all types; empty `additional_projects` means only the primary project. IDs are opaque server identifiers, never filesystem paths or credentials.

MCP success places the validated envelope in `structuredContent`, `isError=false`, and empty `content`; consumers requiring text can negotiate a text-only serialization mode, never duplicate both payloads. Expected domain errors return the Error envelope with `isError=true`; invalid protocol requests remain JSON-RPC errors. Transport authentication failures use HTTP 401/403. Strict FastAPI validation must reject type coercion and nonfinite JSON numbers. HTTP API errors use this Error schema rather than framework-generated payloads containing submitted data.

Enable JSON Schema date-time format assertions explicitly (some validators need an optional RFC3339 validator dependency). Server-side invariants supplement JSON Schema: all timestamps must be UTC RFC3339 with explicit Z; interval end must exceed start; unknown start requires unknown end; enforce expected revisions, matching project/entity/type, and uniqueness in the database. Reject caller-supplied tokenizer selection `configured` when no configured tokenizer exists. A concrete TaskState task_id/BugFix issue_id must match its identity entity. Structured payloads and statements that demonstrably disagree go to review or fail validation; prose is never an overwrite authority.

`resolve_conflict` requires a separately authorized review principal; ordinary ingestion agents cannot self-approve. `accept_candidate` needs a known effective boundary; `coexist` is allowed only for compatible intervals/scopes or set-valued facts, never two overlapping contradictory single-valued accepted facts. A changed conflict head produces `version_conflict` even if its ID is unchanged. Replays return their original logical acknowledgement rather than appending events.

`record_memory` returns a durable ledger outcome, not a promise that vectors are ready. `get_history` fixes `through_seq` on the first page, returns increasing sequence order, and advances `next_after_seq` only over emitted events. History records are sanitized summaries with provenance; complete audit reconstruction uses the authoritative ledger, not these summaries.

`/ingest` is a bounded **source manifest plus structured write** API, not raw transcript upload: 16 entries, at most 8 records each, 256KiB total request body. It rejects cookies, prompt/transcript text fields and arbitrary JSON. Each Source anchor is scrubbed again server-side. A locator is an inert local reference, never automatically fetched/opened by the server. Checkpoint IDs are local opaque bridge handles, not provider bearer/session tokens. Bind adapter/project to the paired principal; nested record project/source identities must match their enclosing entry. `structured` requires records; `needs_agent`/`unavailable` require an empty records array. These cross-field constraints are enforced in addition to schema validation.

One transaction commits batch identity/digest, source manifests, structured write effects/outbox and checkpoint compare-and-swap. Reject the entire batch on validation or version error, with no partial checkpoint advancement. Replayed batch IDs must match the original sanitized digest; preserve the original reply. Checkpoint mismatch returns `version_conflict`. Return HTTP 200 only after durable commit; 429/503 may return a bounded Retry-After. `needs_agent` acknowledges discovery only, not completed extraction; raw chunks remain in the authorized source/bridge, outside engine storage. Source bodies are never returned by these tools.

### 4.3 Hybrid ranking with temporal/project correctness

At request start resolve the authorized union of primary project and explicitly opted-in additional projects (including `global` only when named). Capture ledger cutoff K and effective world time V once; null input means the captured current value. Pin index-generation/config revision for the request and return `embedding_generation` (null when disabled) and `ranking_version`. A repeat is deterministic only with the same K, V, index generation, query, configuration and tokenizer. Never trust a project name inferred by a model as permission.

1. Build the eligible revision set from accepted temporal segments at V/K before channel top-k. Exclude pending/retracted state, unknown applicable intervals, and unresolved competing accepted assertions. Unknown validity is explicitly diagnosed and can be inspected through history. Query-related pending conflicts generate warnings even when no accepted item fits the pack.
2. Exact channel: resolve the structured entity/key/scope match within eligibility; rank exact matches by explicit primary-project preference, type order, memory ID, revision ID. Preserve this channel even if semantic or lexical channels return nothing.
3. Lexical channel: safely tokenize query terms, quote FTS operands rather than accepting arbitrary MATCH syntax, join FTS hits to eligibility before ordering/limit, and sort BM25 ascending then stable IDs. SQLite's [FTS5 BM25](https://www.sqlite.org/fts5.html) uses lower scores for better matches; do not add raw negative BM25 to cosine scores. Its corpus statistics may be shared across projects, but returned candidates must remain scoped. Per-project statistical isolation can be added if required.
4. Semantic channel: embed bounded query chunks with the pinned BGE model, apply matching normalization, and score only eligible indexed revisions using `vec_distance_cosine`. With long queries use bounded tokenizer chunks, mean their embeddings and renormalize; expose partial semantic indexing status. Use SQLite scalar scoring over a materialized eligible relation for the baseline. This is exact distance evaluation, not approximate nearest-neighbor search. Never take global top-k and filter afterward. The extension documents both [scalar cosine and vec0 KNN](https://github.com/asg017/sqlite-vec/blob/main/site/features/knn.md); a later vec0 fast path needs validated filtering for the exact eligible set, not only the project partition.
5. Each channel returns at most 128 eligible revisions (configurable ceiling 512); rank from 1 with stable ID ties. Fuse using `RRF(d) = sum(w_c / (60 + rank_c(d)))`, absent channels contribute zero; proposed initial weights exact=2, lexical=1, semantic=1. These are configurable starting values, not benchmark findings. Sort exact-key matches first, then descending RRF, primary-project preference, type order Decision/Constraint/TaskState/TechStack/BugFix, memory ID and revision ID. Collapse repeated channels and multiple supports to one revision; never merge distinct facts solely by similarity.
6. Revalidate state/scope against the same snapshot before packing; do not let delayed vectors resurrect invalidated revisions. More than one accepted single-valued revision for an overlapping key/time is an invariant violation: fail the read with `unavailable` rather than choose a winner or fabricate a conflict ID. Set-valued assertions can coexist. The service returns provenance badges such as `codex · v3 · 2026-01-01Z` generated from sanitized source metadata, not arbitrary model HTML.

`get_project_context` with a nonempty goal uses the same ranking. Without a goal, skip query embeddings and produce a deterministic type-priority list (Decision, Constraint, TaskState, TechStack, BugFix), then primary-project preference, descending acceptance sequence and stable IDs. The context result does not invent a semantic relevance score; use score=0 in this mode.

Caps and deadlines are explicit recall limitations. If exact-key eligible matches exceed the cap, report `candidate_limit`. For large history eligibility scans, use a bounded deadline and return `historical_scan_limit`/resource error rather than presenting an incomplete search as exhaustive. Missing vectors, stale generations or queue lag return lexical/exact results with `semantic_partial`, `semantic_unavailable` or `index_lag`. Conflict warnings are independent of vector availability.

### 4.4 Deterministic budget packing

Budget applies to canonical `data` JSON, including items, badges, provenance, conflict warnings, diagnostics, snapshot metadata and the Budget object itself. It excludes the constant `ok` envelope, MCP transport framing, discovery schemas and application-added chat wrappers. This precisely scoped bound cannot guarantee the consuming model's total context use. Text-only compatibility mode uses the same canonical data serialization and never duplicates it in structuredContent.

Canonical encoding: UTF-8, sorted object keys, no insignificant whitespace, unescaped Unicode with required JSON control/string escaping, no NaN/Infinity. The Python serialization recipe is `json.dumps(data, sort_keys=True, ensure_ascii=False, separators=(",", ":"), allow_nan=False).encode("utf-8")`; pin runtime/numeric serialization for reproducibility. `configured` uses a pinned local tokenizer/artifact that counts this exact serialization; its identifier appears in `budget.counter`. `utf8_bytes` counts one unit per serialized UTF-8 byte as a conservative bound for supported byte-based tokenizers, explicitly `utf8_upper_bound`, not an exact count for every possible host tokenizer. Hosts with another tokenizer need a configured counter; do not market fallback counts as universal token guarantees. No remote token counting API.

Reserve conflict warnings and fixed metadata first. Sort warnings by project/conflict ID, keep up to 16, and carry the exact remaining count in `conflicts_omitted` plus `more_conflicts`. If warnings exceed the budget, retain fewer and account for them before considering any memories. If even the minimal metadata plus a conflict count cannot fit, return `budget_too_small` with no claimed successful pack.

Walk ranked items once; append an entire item only if the fully serialized candidate still fits. Skip oversized items and continue to smaller later items. Never cut a statement, omit its provenance, or truncate JSON strings to force fit. `limit` caps emitted items, not inspected candidates. Set `truncated=true` if any eligible candidate/warning was omitted due to count/budget/candidate caps. Recompute the full canonical serialization after every change; because `used` changes its own digit count, solve the small fixed point by repeated recount until stable. A final exact count must satisfy `used <= limit`; otherwise remove the lowest-priority item and retry. The fixed metadata minimum is checked before work starts.

For history, preserve ascending event order: stop at the first event that cannot fit, return a continuation, and never skip an oversized event while advancing the cursor. If the next full bounded event cannot fit alone, return `budget_too_small` so the caller can request a larger budget. A read output without items is valid when metadata/warnings consume the budget. Truncation flags describe candidate-limited retrieval, not a promise of exhaustive corpus enumeration.

### 4.5 HTTP mapping and acceptance checks

`POST /v1/tools/{name}` accepts exactly that tool's Input and returns its Output; allow only the five tool names in the registry. `POST /ingest` accepts the bridge Input directly. MCP and REST share business validation, auth scopes, idempotency and error mapping. Domain HTTP codes: 400 invalid input/budget, 401/403 authorization, 404 scoped missing object, 409 expected-version/idempotency/transition conflict, 413 body too large, 429 bounded queue overload, 503 unavailable/resource pressure. Error bodies are fixed schema summaries without submitted content. All responses set Cache-Control: no-store. Full health/config/diagnostic endpoints are loopback-admin surfaces and must never dump source data.

Acceptance fixtures must verify nested unknown-field rejection, timestamp/interval validation, conflicting replay keys, project and review-principal checks, invalid coexistence, all-or-nothing ingest, no raw transcript persistence, independent exact-key candidates, scope/time filtering before top-k, negate/number traps, stable fusion ties, future and unknown validity, conflicting keys withheld, partial vector fallback, full budget serialization (including warnings), multibyte/control characters, tokenizer fallback disclosure, history continuation and stale outbox jobs. Test real CLI testbeds only with synthetic sessions; an 8GB memory/latency benchmark is still required. No personal account testing occurred during research.
